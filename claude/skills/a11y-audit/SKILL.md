# Accessibility audit

`$ARGUMENTS` is one or more local HTML files or URLs. With `--fix`, apply fixes after reporting. Otherwise change nothing.

Cite a success criterion (SC), a line and the offending markup for every finding. Never report a worry without a line to point at. Never say the page "conforms" or "passes AA". A code read cannot verify screen-reader output, real focus order or zoom.

## Step 1 — Load the page

- Read local files in full, with any linked CSS or JS in the repo.
- Fetch URLs with `curl -sL`. Never use WebFetch, which summarises and hides the markup.
- Read the template strings inside scripts. Markup built with `innerHTML` is the real markup.
- Check each state: open dropdowns, revealed results, modals, each mode or tab.
- Find out whether the file is generated. Look for `__PLACEHOLDER__` tokens, a `*_template.*` file, a build script that writes the file, a scheduled workflow that commits it, or a "generated by" comment. Run `git log --stat -3 -- FILE`. Report findings against the generated file, but make every fix in the template or source. A fix made only in the output is overwritten on the next build, and it can vanish between turns. Say which file you are fixing before the first edit.
- Include data files that feed templates. Check the real strings the page prints (addresses, timestamps, names), not just the markup.

## Step 2 — Run the mechanical scans first

Scan every file for these before reading by hand:

```bash
grep -n -E '<html|name="viewport"|user-scalable|maximum-scale' FILE
grep -n -E '<(main|nav|header|footer)\b|skip' FILE
grep -n -E '<h[1-6]' FILE
grep -n -E 'outline: *(none|0)' FILE
grep -n -E '<(div|span|li|tr|td)[^>]*onclick' FILE
grep -n -E 'role="(list|listitem|tab|listbox|option|dialog)"' FILE
grep -n -E '<canvas|<svg|<img' FILE
grep -n -E '<label' FILE
grep -n -E "addEventListener\('click'" FILE
grep -n -E 'aria-(pressed|expanded|live|current|controls)|role="(status|alert)"' FILE
grep -n -E 'prefers-reduced-motion|scroll-behavior' FILE
grep -n -E 'tabindex|inert|aria-modal|\.focus\(' FILE
grep -n -E 'translate(X)?\(-100%|visibility: *hidden|display: *none' CSS
grep -n -E '</style>|<style' CSS
grep -n -E 'font-size: *([0-9]|1[01](\.[0-9])?)px|width: *[0-9]{3,}px' CSS
```

A `</style>` line inside a `.css` file is a leftover from inline styles. The browser reads it as part of the next selector and silently drops the next rule (often `.sr-only`). Fixed `width: NNNpx` values on popups and modals overflow narrow phones. Font sizes under 12px are a readability flag for the design pass.

Also compare CSS to markup. A styled class with no element is usually a missing control: `.skip-link`, `.lightbox-close` and `.sr-only` were all styled but absent from the markup. List the CSS classes whose names suggest an a11y control and grep the markup and script templates for each.

If the page sets a theme or mode class on `<html>` (such as `high-contrast`), read the token block that class selects. Those values are the live ones. Compute contrast from them, not from `:root`.

Then match each result against Step 3.

## Step 3 — Check each area

Mark each as pass, fail or not checkable from source.

**Perceivable**
- 1.1.1 Give every image, canvas and SVG chart a text alternative. A label that names the chart is not enough when the chart carries data. Add a summary or a data table. Mark decorative emoji and icons `aria-hidden`.
- 1.3.1 Keep headings in order. Tie every `<label>` to its control with `for` or by wrapping. Use real lists and tables.
- 1.4.1 Never carry meaning in colour alone. Check chart segments, status badges and active states.
- 1.4.3 Compute contrast. Need 4.5:1 for text, 3:1 for large text (18.66px bold or 24px). Check every text and background pair, in each state.
- 1.4.4 Check the viewport meta allows zoom, and fixed heights do not clip text.
- 1.4.10 Check for horizontal scroll at 320px. Flag fixed-position bars that cover content.
- 1.4.11 Need 3:1 for control boundaries, focus rings, chart marks and meaningful icons. A pale border is a failure when it is the only cue that a field exists.
- 1.4.13 Make tooltips dismissable, hoverable and persistent. A `title` attribute alone is not keyboard reachable.

**Operable**
- 2.1.1 Make everything clickable a `<button>` or `<a href>`. Flag every click listener on a `div`, `span`, `canvas` or table row. Flag actions reachable only by clicking a chart.
- 2.1.2 Close popups on Escape. Never trap focus outside a modal.
- 2.4.1 Provide a skip link or landmarks.
- 2.4.3 Check focus order. Flag any control rebuilt with `innerHTML` right after it was activated, because focus drops to the page. Flag a hidden element that held focus.
- 2.4.4 Make link text meaningful out of context. Flag repeated "see the data →".
- 2.4.7 Keep a visible focus style. Never remove an outline without a replacement.
- 2.5.3 Make the accessible name contain the visible label.

**Understandable**
- 3.1.1 Set `lang` on `<html>`.
- 3.2.1 Never change context on focus.
- 3.3.2 Give every input a label or instruction.

**Robust**
- 4.1.2 Expose role, name and state on custom controls. Add `aria-pressed` to toggle buttons and `aria-expanded` to expanders. Give `role="tab"` a tablist, `aria-controls`, a tabpanel and arrow-key support. If you will not build the full tab pattern, use a `role="group"` of `aria-pressed` toggle buttons. Give `role="listbox"` option children and arrow-key support. Never put a role on an `<a>` that replaces its link role, such as `role="listitem"`.
- 1.3.1 and 4.1.2 Do not put a heading inside a `<button>`. Buttons allow phrasing content only, so the heading role can be dropped. Put the button inside the heading.
- 1.3.1 and 4.1.2 Check list rows that are clickable. A `role="listitem"` on a `div` with a click handler does not announce as actionable. `aria-selected` is invalid on `listitem`. An `aria-label` on the row replaces its content, so ratings, distances and counts are never read. Use `<li><button>` and `aria-current` for the active row. For a long list, use roving `tabindex` instead of `tabindex="0"` on every row. Mark star glyphs `aria-hidden` and give the number a hidden "rating" suffix.
- 2.5.3 Check every `aria-label` that JS sets on a button that has visible text. The visible words must appear in the name. Prefer deleting the `aria-label`. Before you delete it, check whether CSS hides the visible label at some width with `display:none` (common for icon-only mobile buttons). That leaves no name. Use a visually-hidden style instead.
- 4.1.3 Announce changes that happen without a focus move. Use `aria-live` or `role="status"` for results, counts and errors (including "12 stalls matching…"). Use `role="alert"` for load failures. Replace `alert()` for errors with an inline status message.
- Dialogs: move focus in when opened, trap it (or set the page behind to `inert`), and return focus on close. `aria-modal` alone does none of this. Check the dialog sits at the body root. A dialog nested inside the content that is made inert is made inert with it.
- Overlays that look like dialogs (lightbox, image viewer): require `role="dialog"`, `aria-modal`, a real close button (not only click-anywhere or Esc), focus in and back, and a live announcement of "n of N" on navigation. A static `alt` on the shown image is a failure.
- Off-screen UI: a drawer hidden with `transform: translateX(-100%)` stays focusable and readable. Require `inert` or `visibility: hidden` while closed, and `aria-expanded` and `aria-controls` on the toggle. If code focuses something inside the drawer right after opening it, un-inert first. A MutationObserver runs a tick too late.
- Hover tooltips: give the trigger `tabindex="0"` and `aria-describedby`, show on `:focus-within`, and dismiss with Esc without moving focus. Click-toggled tooltips need `aria-expanded`, `aria-controls` and Esc. Check tooltip width against the container (a 360px tooltip inside a 350px overflow-hidden sidebar clips).
- Map widgets (Leaflet, Mapbox): the popup does not take focus, and its pane sits after the marker pane in the DOM. Require focus to move into the popup on open and back to the trigger on close. `L.marker` with a `divIcon` is a focusable `role="button"` with no name. Set `aria-label` in `marker.on('add', …)`, because clusters re-create the element. Check that the list of results gives the map's actions a non-map route.
- Third-party CSS wins on specificity. Leaflet's `.leaflet-container a` paints popup links `#0078A8` over your own `.link` rule, which also breaks your contrast numbers. Compute colours from the browser (`getComputedStyle`), not from your rules.
- Flag missing ids, duplicate ids and invalid ARIA.

## Step 3b — Verify in a browser

Do this whenever a browser tool is available. A code read misses layout, cascade and focus problems.

- Detect Playwright with `uv run python -c "import playwright"` or `ls ~/Library/Caches/ms-playwright`. Serve the folder with `python3 -m http.server PORT --directory DIR`. A server started from the wrong directory returns 404 for the page.
- Probes worth running: `header.scrollWidth` against `clientWidth` at 320 and 375px (fixed headers with `nowrap` badges overflow); popup width and close-button position at 320px (a fixed `width: 320px` popup overflows a 320px phone); whether floating map controls overlap the popup's close button; `getComputedStyle(document.activeElement).outline*` on popup controls (`transition: all` can report a 0px ring); bounding boxes of every control (tap targets of 24px or more, 32px or more preferred); marker `role`, `tabindex` and `aria-label`; computed `position` of every `.sr-only` element; and the Tab, Esc and Enter flows for each dialog, drawer and popup.
- Check the failure paths too: block the data request (`page.route('**/data.json', r => r.abort())`) and deny geolocation. Confirm the page shows a message and does not loop.
- Take screenshots at 1200, 375 and 320px after any mechanical CSS change (text size floors, tap-target padding, radii). Larger text and padding wrap rows, clip fixed-height pills and push controls onto new lines.
- Playwright traps: `page.evaluate("fn = () => {}")` calls the function it just assigned. Wrap the statement: `() => { fn = ...; }`. Use a unique viewport and `has_touch` / `is_mobile` for phone checks, and `.tap()` instead of `.click()` there.
- No Node on the machine? Syntax-check inline scripts with macOS's `/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc -e 'new Function(readFile("f.js"))'`.

## Step 4 — Compute contrast

Never estimate. Extract the real colour pairs from the CSS tokens and from inline styles and script colour maps. Compute them:

```bash
python3 -I - <<'PY'
def lum(h):
    h = h.lstrip('#')
    if len(h) == 3: h = ''.join(c*2 for c in h)
    r, g, b = (int(h[i:i+2], 16)/255 for i in (0, 2, 4))
    f = lambda c: c/12.92 if c <= 0.03928 else ((c+0.055)/1.055)**2.4
    return 0.2126*f(r) + 0.7152*f(g) + 0.0722*f(b)
def ratio(a, b):
    la, lb = sorted((lum(a), lum(b)), reverse=True)
    return (la+0.05)/(lb+0.05)
pairs = [("#6b7280", "#f8f8f6")]  # replace with the page's real pairs
for fg, bg in pairs:
    print(fg, "on", bg, round(ratio(fg, bg), 2))
PY
```

Compute the accent colour on every tint it appears on (white, page background, a "light" accent fill, a noodle or paper tint, an active-card fill). Accent text that passes on white often fails by a hair on the tinted fills (4.0 to 4.5). Compute text blended through `opacity` (child spans at `.65` or `.85` are common), border colours against the page background for 1.4.11, and star or icon colours against their fill. When darkening a token, choose one value that clears 4.5:1 on every surface it is used on, then show each pair.

Check these pairs on every page: muted text on each surface tint, white text on each accent and chart colour, coloured text on white, bar fills on their tracks, and borders on their backgrounds. Compute the opacity-blended colour for any text set with `opacity`.

## Step 5 — Report

Sort findings by severity.

| Severity | Meaning |
|---|---|
| **Blocker** | Stops a keyboard or screen-reader user finishing a task |
| **Major** | Fails an AA criterion, with a workaround |
| **Minor** | Fails an AA criterion in a low-impact spot, or best practice |

Format each finding:

```
[Major] 1.4.3 Contrast — index.html:131
  .hygiene-note #6b7280 on #f0f0ed = 4.23:1, needs 4.5:1
  Fix: darken to #5b6370 (5.3:1)
```

Finish with:
- A count by severity.
- The three fixes with the most impact.
- A "not verified from source" list: screen-reader output, real focus order, zoom and reflow, motion. Offer a browser pass if a browser tool is available.

When auditing several pages, report shared problems once and list the pages they affect.

Hand off what is not accessibility. Markup built with `innerHTML` from data attributes or scraped data (author names, links, IDs) is an XSS risk. Mention it in one line and point to a security audit. Do not fix it in an a11y pass.

Rank Blockers by whether a keyboard-only user can finish the main task: open an item, read it, act on it, and close it. Dialogs without focus management and popups that never take focus have been the top findings.

## Step 6 — Fix (only with `--fix`)

Confirm the file to edit first (Step 1: generated or source). Check `git status` and `git log -3` before the first edit and again before each batch. If a scheduled job commits the file, your edits can be overwritten or reverted between turns, so re-check with a grep for something you added. Edit the template and source, then mirror the same change into the generated output so the live site updates before the next build. A small helper that applies each edit to both files and asserts the pattern matches exactly once keeps them in step. Placeholders such as `__GROUP_URL__` differ between the two files, so anchor edits on text that is identical in both.

Fix one finding at a time with Edit. Make the smallest change: a token colour, an attribute, a `div` to a `button`. Never restyle the page. Re-run the contrast script on every colour changed and show the new ratio. Mark a finding fixed only when the edit is in the file and a browser check (Step 3b) shows it works.

If the user asks for one commit per change, commit after each finding with a message like `a11y: <what changed>`. Follow the repo's commit rules and the user's attribution rules. Never push unless asked. Offer it, and check `git fetch` shows the branch is not behind first.

Pitfalls seen while fixing:
- Order of declarations. A `let` or `const` used by a function that runs at load time must be declared above the call (a `let` declared lower down is in its temporal dead zone). Function declarations hoist, `let` does not.
- A fix can remove a name. Deleting an `aria-label` left the icon-only mobile button nameless. Re-check the narrow layout.
- A fix can break a loop guard. A "refresh the popup when data arrives" callback re-registered itself when the fetch failed, which would loop forever. Add a failure flag and test the failure path.
- Making text larger or padding bigger wraps rows. Check every row you touched (sort pills, filter pills, header) at 320px.
- Do not change values sent to external systems. A report form still needs the raw address even when the UI shows a cleaned name.
- Delete dead code by reference scan: collect the class names and function names the markup and scripts use, then remove CSS rules and functions that nothing references. Run the browser checks again afterwards.
