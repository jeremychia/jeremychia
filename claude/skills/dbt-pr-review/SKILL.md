# dbt PR review

Ask each question below of every model the PR adds or changes. Answer what the repo shows yourself. Post a question only where the author or the data holds the answer. Sections run from the most-asked question to the least. Each link is a real review comment that asks it.

## 1. Grain and joins

- **Does this join fan out rows?** Find the key on each side. Check it is unique on the joined table. ([marketplace#18897](https://github.com/vinted/dataverse-marketplace-dbt/pull/18897#discussion_r4163608036), [experimentation#462](https://github.com/vinted/dataverse-experimentation-dbt/pull/462#discussion_r2634957525), [sustainability#445](https://github.com/vinted/dataverse-sustainability/pull/445#discussion_r3378734022))
- **Is this an unintended cartesian or self join?** Check whether a flag set by the join is true on every row. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155228886), [marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155369319))
- **Does a new row type double existing sums?** A seller row and a buyer row per transaction doubles every Look that sums. ([finance#2241](https://github.com/vinted/dataverse-finance/pull/2241#discussion_r4006108182))
- **Is a dedup hiding a join that explodes?** Ask for the join to be fixed, not deduplicated after. ([groupfunctions#857](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/857#discussion_r3459875750))
- **Is the dedup deterministic, and is it needed?** Check the `order by` cannot tie, and that duplicates exist at all. ([experimentation#928](https://github.com/vinted/dataverse-experimentation-dbt/pull/928#discussion_r4184104340), [experimentation#889](https://github.com/vinted/dataverse-experimentation-dbt/pull/889#discussion_r3976922210))
- **Does the dedup run before the filter?** Filtering deleted rows first lets a stale version survive. ([experimentation#360](https://github.com/vinted/dataverse-experimentation-dbt/pull/360#discussion_r2362702882))
- **Is the merge `unique_key` really unique?** ([groupfunctions#1041](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1041#discussion_r3933853839))
- **Is a validity join point-in-time, with the right bounds?** Check `>=` against `<`, and whether "current record" was meant. ([sustainability#405](https://github.com/vinted/dataverse-sustainability/pull/405#discussion_r3098732447), [sustainability#456](https://github.com/vinted/dataverse-sustainability/pull/456#discussion_r3434092765))
- **Does a simpler join do the same?** Replace a cross join, or two inner joins plus a union, with one left join. ([sustainability#463](https://github.com/vinted/dataverse-sustainability/pull/463#discussion_r3570934436), [sustainability#290](https://github.com/vinted/dataverse-sustainability/pull/290#discussion_r2589408207))

## 2. Incremental window

- **Does the date come from the scheduler, not the clock?** Use `data_interval_end` or `data_interval_start`, not `current_date()` or the first of `partitions_to_replace`. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155346071), [groupfunctions#933](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/933#discussion_r3713648215), [metrics#219](https://github.com/vinted/dataverse-metrics/pull/219#discussion_r2410378561))
- **Why this many partitions?** Ask for one day unless data arrives late. Ask whether one day misses late arrivals. ([groupfunctions#608](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/608#discussion_r3026660208), [groupfunctions#1072](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1072#discussion_r3977277762), [sustainability#339](https://github.com/vinted/dataverse-sustainability/pull/339#discussion_r2840487380))
- **Is the window filter inside `is_incremental()`?** A filter on both sides of the block always applies, so a full refresh loads only the window. ([marketplace#19022](https://github.com/vinted/dataverse-marketplace-dbt/pull/19022#discussion_r4207978724))
- **Does an incremental model have a `unique_key` and an `is_incremental()` block at all?** ([sustainability#495](https://github.com/vinted/dataverse-sustainability/pull/495#discussion_r3749545799), [sustainability#352](https://github.com/vinted/dataverse-sustainability/pull/352#discussion_r2857981360))
- **Does a widened lookback leak into the output?** Extra days read for a rolling window must not be written. A full refresh must not write days before the start date. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155356347), [marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4203902736))
- **Do a full refresh and an incremental run give the same answer?** A `lag()` over rows differs when the window drops a month. ([finance#2360](https://github.com/vinted/dataverse-finance/pull/2360#discussion_r4082148786))
- **Does it work when run by hand?** Check the default of every interval var, and the empty data in CI. ([finance#2374](https://github.com/vinted/dataverse-finance/pull/2374#discussion_r4192993210), [finance#2309](https://github.com/vinted/dataverse-finance/pull/2309#discussion_r4004148874))
- **Does a rerun give the same rows?** ([competitive-intelligence#158](https://github.com/vinted/dataverse-competitive-intelligence/pull/158#discussion_r2240539623))
- **Does an incremental model list its columns and set `on_schema_change`?** ([vintedgo#3360](https://github.com/vinted/dataverse-vintedgo-dbt/pull/3360#discussion_r1910591902), [vintedgo#3360](https://github.com/vinted/dataverse-vintedgo-dbt/pull/3360#discussion_r1910592428))
- **Is the lookback long enough for late records**, such as credit notes or duplicates? ([vintedgo#5005](https://github.com/vinted/dataverse-vintedgo-dbt/pull/5005#discussion_r2256541791), [vintedgo#4542](https://github.com/vinted/dataverse-vintedgo-dbt/pull/4542#discussion_r2128307834))
- **Is the usual pattern used?** Prefer `date(x) in ({{ partitions_to_replace | join(",") }})` or `shared.get_partitions_to_replace`. ([marketplace#18870](https://github.com/vinted/dataverse-marketplace-dbt/pull/18870#discussion_r4144541637), [sustainability#425](https://github.com/vinted/dataverse-sustainability/pull/425#discussion_r3168632726))

## 3. Cost

- **Does every read of a big table filter on its partition column?** ([vintedgo#9709](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9709#discussion_r4166166738), [finance#2226](https://github.com/vinted/dataverse-finance/pull/2226#discussion_r4023837420), [marketplace#18995](https://github.com/vinted/dataverse-marketplace-dbt/pull/18995#discussion_r4183389577))
- **Is a big source scanned once, not in three models?** ([marketplace#18897](https://github.com/vinted/dataverse-marketplace-dbt/pull/18897#discussion_r4163634648))
- **What does a full refresh cost?** Name the terabytes. Ask for `full_refresh=false` on a huge source. ([marketplace#19094](https://github.com/vinted/dataverse-marketplace-dbt/pull/19094#discussion_r4220010199), [marketplace#18988](https://github.com/vinted/dataverse-marketplace-dbt/pull/18988#discussion_r4183135395))
- **Should a large table be incremental?** ([vintedgo#9378](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9378#discussion_r3895659746))
- **Is the table big enough to partition?** Under 10 GB, cluster instead. ([vintedgo#4542](https://github.com/vinted/dataverse-vintedgo-dbt/pull/4542#discussion_r2128287504), [vintedgo#6660](https://github.com/vinted/dataverse-vintedgo-dbt/pull/6660#discussion_r2606833600))
- **Does the logic cost a lot per row?** A date or minute array per row can explode. Ask for direct arithmetic. ([vintedgo#4779](https://github.com/vinted/dataverse-vintedgo-dbt/pull/4779#pullrequestreview-3009532220), [vintedgo#6130](https://github.com/vinted/dataverse-vintedgo-dbt/pull/6130#discussion_r2485881235))
- **Do clustering columns match how people filter?** Check the column order too. ([groupfunctions#608](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/608#discussion_r3008548926), [marketplace#18928](https://github.com/vinted/dataverse-marketplace-dbt/pull/18928#discussion_r4163752204), [experimentation#181](https://github.com/vinted/dataverse-experimentation-dbt/pull/181#discussion_r1686263907))
- **Does the config take effect?** A view ignores partitioning, clustering and unique keys. ([experimentation#291](https://github.com/vinted/dataverse-experimentation-dbt/pull/291#discussion_r2055674503), [sustainability#425](https://github.com/vinted/dataverse-sustainability/pull/425#discussion_r3172779535))
- **Is the materialization right?** Keep staging as a view. Make a pass-through model a view. ([experimentation#378](https://github.com/vinted/dataverse-experimentation-dbt/pull/378#discussion_r2413717889), [groupfunctions#1019](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1019#discussion_r3880620823))
- **Is there a dry run for a risky scan?** Ask for one where pruning could fail. ([finance#2209](https://github.com/vinted/dataverse-finance/pull/2209#discussion_r3959136131))

## 4. Layering

- **Is a mart reading a mart, or a prep reading a mart?** Point to the fact or dim to use instead. ([marketplace#19045](https://github.com/vinted/dataverse-marketplace-dbt/pull/19045#discussion_r4205726299), [marketplace#18884](https://github.com/vinted/dataverse-marketplace-dbt/pull/18884#discussion_r4153873465), [vintedgo#9465](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9465#discussion_r3968992317))
- **Is it reading another project's intermediate model?** ([marketplace#19056](https://github.com/vinted/dataverse-marketplace-dbt/pull/19056#discussion_r4216920342))
- **Is cleaning in staging?** Dedup, cast and rename there, not in a mart. ([groupfunctions#985](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/985#discussion_r3854631877), [groupfunctions#918](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/918#discussion_r3620965072), [competitive-intelligence#935](https://github.com/vinted/dataverse-competitive-intelligence/pull/935#discussion_r4216824042))
- **Is a source imported where the domain already imports it?** ([sustainability#291](https://github.com/vinted/dataverse-sustainability/pull/291#discussion_r2613312814))
- **Should this be a Looker measure or table calculation instead?** ([metrics#579](https://github.com/vinted/dataverse-metrics/pull/579#discussion_r3765439458), [marketplace#18814](https://github.com/vinted/dataverse-marketplace-dbt/pull/18814#discussion_r4154943144))
- **Should the source be fixed upstream instead of remapped here?** ([experimentation#733](https://github.com/vinted/dataverse-experimentation-dbt/pull/733#discussion_r3441186990))

## 5. Reuse

- **Does a model, macro or pattern already do this?** Link the existing one at a pinned commit. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155210857), [marketplace#18874](https://github.com/vinted/dataverse-marketplace-dbt/pull/18874#discussion_r4146208797), [experimentation#378](https://github.com/vinted/dataverse-experimentation-dbt/pull/378#discussion_r2415876993))
- **Is the same rule now defined in two places?** Move a repeated constant to `vars:`. Join the shared dim instead of keeping a copy. ([finance#2222](https://github.com/vinted/dataverse-finance/pull/2222#discussion_r3959496275), [groupfunctions#857](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/857#discussion_r3459857602))
- **Is a block repeated?** Ask for a jinja loop, an `unpivot` or a macro. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155402973), [vintedgo#9374](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9374#discussion_r3903458628), [experimentation#426](https://github.com/vinted/dataverse-experimentation-dbt/pull/426#discussion_r2570979940))
- **Is this column already on the fact?** ([vintedgo#9407](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9407#discussion_r3922063679))

## 6. Nulls and edge cases

- **Can this column be null, and what happens then?** Check `concat`, `not in`, `unpivot` and joins on it. ([marketplace#19105](https://github.com/vinted/dataverse-marketplace-dbt/pull/19105#discussion_r4220027736), [groupfunctions#1041](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1041#discussion_r3933906813), [marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4203902750))
- **Does a default invent data?** Keep null rather than `9999-12-31`, `false` or an empty string. Handle an open end in the join, with `valid_to is null or ...`. ([groupfunctions#922](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/922#discussion_r3922209836), [sustainability#463](https://github.com/vinted/dataverse-sustainability/pull/463#discussion_r3570436858), [experimentation#539](https://github.com/vinted/dataverse-experimentation-dbt/pull/539#discussion_r2817182527))
- **Does a coalesce merge "no" with "not found"?** ([finance#2226](https://github.com/vinted/dataverse-finance/pull/2226#discussion_r4023785433))
- **Does `safe_divide` hide a case to handle?** Decide what a zero denominator means, and write that case out. ([sustainability#425](https://github.com/vinted/dataverse-sustainability/pull/425#discussion_r3168677538))
- **What about a group with no rows, a late record or a fix the next day?** ([sustainability#408](https://github.com/vinted/dataverse-sustainability/pull/408#discussion_r3123474109), [metrics#271](https://github.com/vinted/dataverse-metrics/pull/271#discussion_r2584346976), [marketplace#18637](https://github.com/vinted/dataverse-marketplace-dbt/pull/18637#discussion_r4182082145))
- **Does an aggregate pick the right value?** `max()` on a version string ranks `2.9.0` above `2.10.0`. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4203902765))

## 7. Business logic

- **Does the definition match the real event and its sibling metrics?** Check creation date against publication date, and add against subtract. ([marketplace#18992](https://github.com/vinted/dataverse-marketplace-dbt/pull/18992#discussion_r4182878107), [competitive-intelligence#527](https://github.com/vinted/dataverse-competitive-intelligence/pull/527#discussion_r3086512502), [metrics#152](https://github.com/vinted/dataverse-metrics/pull/152#discussion_r2137335516))
- **Has the assumption been checked against the data?** ([sustainability#457](https://github.com/vinted/dataverse-sustainability/pull/457#discussion_r3429510053), [sustainability#356](https://github.com/vinted/dataverse-sustainability/pull/356#discussion_r2863663479))
- **Does it still hold after a product change?** ([marketplace#19068](https://github.com/vinted/dataverse-marketplace-dbt/pull/19068#discussion_r4217210964))
- **Where does this number, threshold or start date come from?** Ask for the reason in the yml. ([groupfunctions#933](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/933#discussion_r3713669815), [finance#2226](https://github.com/vinted/dataverse-finance/pull/2226#discussion_r4023821996), [vintedgo#9729](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9729#discussion_r4166368065))
- **Will a hardcoded list break when a market, city or category is added?** Prefer a seed, a mapping or the source column. ([sustainability#430](https://github.com/vinted/dataverse-sustainability/pull/430#discussion_r3194309361), [vintedgo#9779](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9779#discussion_r4215864636), [competitive-intelligence#677](https://github.com/vinted/dataverse-competitive-intelligence/pull/677#discussion_r3379322411))
- **Are test users, deleted records and suspicious users handled on purpose?** ([marketplace#18928](https://github.com/vinted/dataverse-marketplace-dbt/pull/18928#discussion_r4163740435), [marketplace#18958](https://github.com/vinted/dataverse-marketplace-dbt/pull/18958#discussion_r4192069624), [marketplace#18992](https://github.com/vinted/dataverse-marketplace-dbt/pull/18992#discussion_r4182996274))
- **Does the column mean the same across every source or channel?** Check that ids that join to users go through id consolidation. ([groupfunctions#1041](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1041#discussion_r3915295538), [experimentation#9](https://github.com/vinted/dataverse-experimentation-dbt/pull/9#discussion_r1446333884))
- **Does a string match survive casing and format?** Check the value actually occurs on prod. ([experimentation#363](https://github.com/vinted/dataverse-experimentation-dbt/pull/363#discussion_r2371764258), [finance#2484](https://github.com/vinted/dataverse-finance/pull/2484#discussion_r4196151256))

## 8. Unused and redundant code

- **Is each column, CTE and constant used downstream?** ([marketplace#18884](https://github.com/vinted/dataverse-marketplace-dbt/pull/18884#discussion_r4154052697), [experimentation#784](https://github.com/vinted/dataverse-experimentation-dbt/pull/784#discussion_r3712134547))
- **Is this filter already applied upstream, or true of every row?** ([sustainability#525](https://github.com/vinted/dataverse-sustainability/pull/525#discussion_r4038647546), [vintedgo#9410](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9410#discussion_r3923268565), [metrics#526](https://github.com/vinted/dataverse-metrics/pull/526#discussion_r3672824990))
- **Does every column earn its place in the mart?** Drop segments nobody will slice by. ([experimentation#356](https://github.com/vinted/dataverse-experimentation-dbt/pull/356#discussion_r2321333133))
- **Is the config line just the default?** ([vintedgo#9411](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9411#discussion_r3924680654), [vintedgo#9729](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9729#discussion_r4166385632))
- **Is code commented out?** Delete it, because git keeps the history. ([vintedgo-looker#2572](https://github.com/vinted/dataverse-vintedgo-looker/pull/2572#pullrequestreview-3126971109), [competitive-intelligence#99](https://github.com/vinted/dataverse-competitive-intelligence/pull/99#discussion_r2191861679))
- **Is a CTE identical to the one before it?** ([experimentation#292](https://github.com/vinted/dataverse-experimentation-dbt/pull/292#discussion_r2047028544))

## 9. Naming and style

- **Does the name follow convention?** Use `num_` for counts, `is_` or `has_` for booleans, `_at` for timestamps and plural model names. ([groupfunctions#985](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/985#discussion_r3854663454), [groupfunctions#1026](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1026#discussion_r3894758650), [experimentation#713](https://github.com/vinted/dataverse-experimentation-dbt/pull/713#discussion_r3347558860), [experimentation#760](https://github.com/vinted/dataverse-experimentation-dbt/pull/760#discussion_r3450979339))
- **Does the name say what the column holds, and match sibling tables?** Avoid abbreviations. Never reuse an input's name for a derived value. ([marketplace#18967](https://github.com/vinted/dataverse-marketplace-dbt/pull/18967#discussion_r4183986605), [sustainability#545](https://github.com/vinted/dataverse-sustainability/pull/545#discussion_r4152854530), [groupfunctions#822](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/822#discussion_r3394687789))
- **Are there table aliases?** Use full names for lineage. Drop the prefix when a CTE reads one table. ([marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902#discussion_r4155219311), [metrics#125](https://github.com/vinted/dataverse-metrics/pull/125#discussion_r2007099137), [vintedgo#9709](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9709#discussion_r4166091038))
- **Does the SQL follow the style guide and linter?** Use import CTEs, CTEs not subqueries, `group by all`, lowercase and explicit columns. ([metrics#488](https://github.com/vinted/dataverse-metrics/pull/488#discussion_r3458430677), [sustainability#299](https://github.com/vinted/dataverse-sustainability/pull/299#discussion_r2627138299), [marketplace#18988](https://github.com/vinted/dataverse-marketplace-dbt/pull/18988#discussion_r4183145166), [vintedgo#9491](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9491#discussion_r3989555007))
- **Does an amount or duration name its currency, unit or timezone?** Use suffixes such as `_eur`, `_invoice_currency` or `_utc`. ([vintedgo#4769](https://github.com/vinted/dataverse-vintedgo-dbt/pull/4769#discussion_r2194651791), [vintedgo#5807](https://github.com/vinted/dataverse-vintedgo-dbt/pull/5807#discussion_r2428509877))
- **Could the model name be confused with another domain's model?** ([vintedgo#2999](https://github.com/vinted/dataverse-vintedgo-dbt/pull/2999#discussion_r1860585473))
- **Is the data type right?** Use booleans not ints, and a string for ids too long for a float. ([metrics#125](https://github.com/vinted/dataverse-metrics/pull/125#discussion_r2007098231), [marketplace#19003](https://github.com/vinted/dataverse-marketplace-dbt/pull/19003#discussion_r4185471201))
- **Is a hardcoded project id or date a var or `{{ target.database }}`?** ([groupfunctions#951](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/951#discussion_r3794850638), [finance#2437](https://github.com/vinted/dataverse-finance/pull/2437#discussion_r4153902077))
- **Will the name read well in Looker?** ([competitive-intelligence#801](https://github.com/vinted/dataverse-competitive-intelligence/pull/801#discussion_r3688558830))

## 10. Docs

- **Does the description match the SQL?** Check the comparison operators, the windows and the configs it claims. ([marketplace#19018](https://github.com/vinted/dataverse-marketplace-dbt/pull/19018#discussion_r4195683979), [marketplace#18915](https://github.com/vinted/dataverse-marketplace-dbt/pull/18915#discussion_r4154595714), [finance#2360](https://github.com/vinted/dataverse-finance/pull/2360#discussion_r4082133353))
- **Does it state the grain and partition first, in plain words?** ([metrics#152](https://github.com/vinted/dataverse-metrics/pull/152#discussion_r2137296321), [experimentation#19](https://github.com/vinted/dataverse-experimentation-dbt/pull/19#discussion_r1455282511), [marketplace#19038](https://github.com/vinted/dataverse-marketplace-dbt/pull/19038#discussion_r4204676781))
- **Was the yml copied from another model and left wrong?** ([finance#2209](https://github.com/vinted/dataverse-finance/pull/2209#discussion_r3959097247), [finance#2222](https://github.com/vinted/dataverse-finance/pull/2222#discussion_r3959573221))
- **Does it reuse the existing doc block, worded the same as upstream?** Change a shared description everywhere it appears. ([experimentation#835](https://github.com/vinted/dataverse-experimentation-dbt/pull/835#discussion_r3803456731), [vintedgo#9349](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9349#discussion_r3901807013))
- **Is every new term defined, and every limit stated?** ([vintedgo#9519](https://github.com/vinted/dataverse-vintedgo-dbt/pull/9519#discussion_r4016516346), [groupfunctions#939](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/939#discussion_r3729142350))
- **Does a comment say why, not restate the SQL?** Ask for one on any filter or constant whose reason is not obvious. Ask to move history and temporary notes to the PR. ([metrics#262](https://github.com/vinted/dataverse-metrics/pull/262#discussion_r2549927823), [metrics#219](https://github.com/vinted/dataverse-metrics/pull/219#discussion_r2410295354), [groupfunctions#1028](https://github.com/vinted/dataverse-groupfunctions-dbt/pull/1028#discussion_r3894894023))

## 11. Tests

- **Can this data test fail, and what does it scan?** Drop one that upstream tests already cover or the model guarantees. ## Worked case

[marketplace#18902](https://github.com/vinted/dataverse-marketplace-dbt/pull/18902) added a rolling 7-day active-user count to `mrt_third_party_toggle_opt_ins`. One human pass and one bot pass found these:

- **Grain.** Every user in `joined` was active on the target date, so the 7-day join matched all of them. `is_active_7d` was true on every row, and users active earlier in the week were lost.
- **Reuse.** Three `union all` blocks differed only in a hardcoded toggle. An `unpivot`, copied from `mrt_monthly_cmp_opt_outs`, replaced them. A date spine from the same model replaced `select distinct`.
- **Window.** The end date came from `partitions_to_replace`, so a run with more partitions would shift it. `data_interval_end` fixed it. A full refresh wrote days before the start date until a filter was added.
- **Nulls.** `unpivot` drops null values, so users without a settings row lost their third-party row. A `coalesce(..., false)` fixed it.
- **Downstream.** `user_type` changed from `new` to `New`, which would have emptied Looker filters. It went back to lowercase.
- **Deployment.** The clustering change needed a full refresh, so it went into the to-do list.
