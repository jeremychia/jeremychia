Distilled from the raw PDFs in this folder so the recurring signal doesn't require re-opening all of them each time. Update this file after each new quarterly/annual review lands — pull out anything that repeats across 2+ cycles or that's a strong quotable metric.

Source PDFs cover 2023 Q3 through 2025 Q4 & Annual (Vinted, Analytics Engineer / VGo Analytics Engineering, manager: Georgi Evlogiev).

## Recurring strengths (2+ reviews)

- **Ownership on ambiguous, cross-team problems** — repeatedly cited for picking up work "out of my sphere of influence" and driving it to done (e.g. Looker executions cost/usage dataset, invoice completeness alerts, price list migration success metrics).
- **Testing rigour** — raised `vgo_finance` dbt unit test coverage from ~1% to 50%+ over one quarter (2025 Q4); created an instruction sheet other engineers (Arabella, Quirine) reused to write their own tests.
- **Knowledge sharing / enablement** — recurring theme across reviews: onboarding materials for DSA Academists built from scratch, a dbt Meetup hosted internally, a testing-strategy talk at Forward Data Conference. Nominated for "AE of the Year" (2025).
- **Co-creation with cross-functional partners** — Data Catalog initiative, price list migration, called out specifically as strong collaboration with PM and Data Platform.

## Recurring growth areas (2+ reviews)

- **Cost control / query efficiency** — flagged as a "recurring theme for 2025" by the manager directly: optimisation attempts were real but not durable, costs kept climbing. This is the single most-repeated critique across cycles — treat as the top gap to address if a JD emphasises FinOps/cost ownership, and don't overclaim cost-reduction wins without qualifying that this was an ongoing struggle.
- **Focus vs. breadth** — manager feedback (2025 Annual): "the most impactful lever at your disposal is greater focus on fewer topics at a time." Too many concurrent threads diluted depth on any one.
- **Work/life boundaries** — noted as a pattern (weekend PRs, reviewing outside working hours) with the manager framing it as a poor precedent to set, not a strength to lean on in interviews.

## How to use this file

- When writing a new STAR story, check here first for a review-sourced example with a manager quote attached — external validation reads stronger than self-reported achievements.
- When `/adapt-resume` surfaces a JD gap around cost management or FinOps, this file has the honest answer: real attempts, acknowledged as insufficient. Use the honest framing in cover letter P3 rather than claiming a clean win.
- Re-open the underlying PDF only when this summary doesn't have enough texture for the specific story being written.
